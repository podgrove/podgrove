# Podgrove documentation

Register: brand — documentation landing and technical reference.

Developers and coding agents arrive with an existing Compose application, often several Git worktrees, and an approved development cluster. They need to understand what Podgrove moves, what stays local, how to install it, and where platform setup fits. Maintainers also need precise configuration and operational references.

The landing page introduces the worktree model and leads into the authoritative guides. It does not replace their setup instructions. Installation, generated namespace manifests and explicit configuration precede the first `up`. Homebrew must not appear available until it is actually published.

The voice is calm, familiar and precise. Preserve the established Pods logo, terracotta accent, neutral light and dark surfaces, Avenir/system body text, and Iowan/Palatino display type. The physical setting is a developer reading setup beside an editor, in either a bright office or a dim evening workspace; support their selected theme equally.

Use native Starlight navigation, search, theme selection, code examples and documentation structure. The landing diagram explains local worktrees and separate Kubernetes engines; no synthetic metrics or invented dashboard state. Prefer prose, ordered setup steps and guide rows over marketing cards.

Success means a reader can identify the runtime model, find verified installation and namespace setup, and reach the right configuration or operations guide. All content is usable at 320 CSS pixels, with keyboard navigation, a single continuous focus boundary, reduced motion and sufficient contrast. Keep the generated reference pages sourced from the repository documentation.
